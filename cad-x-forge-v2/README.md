# CAD x FORGE — магазин цифровых лекал в Telegram

Telegram-бот → Mini App (магазин) → оплата Telegram Stars → «Покупки» → защищённое скачивание файлов.
Админка — `/admin/` (открывается внутри Telegram, только для вашего Telegram ID).

## 1. Архитектура

```
Telegram ─ бот (webhook) ──┐
Mini App (GitHub Pages) ───┼──▶ Cloudflare Worker (API) ──▶ D1  (база: товары, заказы, пользователи)
Админка (GitHub Pages) ────┘                           └──▶ R2  (приватное хранилище: изображения и файлы лекал)
```
* **Единственный источник данных — база D1.** `localStorage` используется только для корзины и выбранного языка на устройстве.
* Файлы лекал лежат в закрытом R2 и отдаются только по временным подписанным ссылкам после проверки покупки.
* Цена и состав заказа считаются только на сервере. Оплата засчитывается только по подтверждённому Telegram платежу (webhook).

Папки: `worker/` — backend (TypeScript), `worker/migrations/` — миграции БД (`0001`–`0003`), `seed/` — демо-товары (необязательно),
`index.html`, `admin/index.html`, `config.js`, `api.js` — фронтенд.

**Версия 2 (V3-пакет 1):** варианты товара «размер × рост» с отдельными файлами, загрузка больших файлов по частям с продолжением, видео (потоковое воспроизведение по Range), редактируемые страницы («Инфо», FAQ, документы) и меню, справочники с перетаскиванием и зонами «рабочая область / неиспользуемые», правки интерфейса магазина (RU/EN/KAZ, чёрная шапка, лупа, стрелки галереи, зелёные кнопки покупки).

## 1а. Обновление с версии 1 (если v1 уже развёрнута)

1. **Резервная копия базы.** Если в магазине уже есть товары, заказы или покупатели — сначала сохраните копию базы D1 (экспорт базы или восстановление на момент времени в панели Cloudflare; точный пункт меню проверьте в вашем интерфейсе). Если магазин ещё пустой, копия не нужна.
2. **Миграция:** D1 → ваша база → Console → выполните содержимое `worker/migrations/0003_variants_pages_menu.sql` **целиком или блоками по порядку** (блоки разделены пустыми строками; порядок важен). Миграция добавляет таблицы и пересобирает `purchases` и `order_items` с копированием данных.
3. **Сразу после миграции** загрузите новые файлы в GitHub (шаг 4). Между миграцией и обновлением Worker (около минуты) **не принимайте платежи**: старый код не знает новой структуры покупок.
4. **Что заменить в репозитории:** `index.html`, `admin/index.html`, `api.js`, `README.md`, папки `worker/src`, `worker/test`, `worker/migrations`, `worker/package.json`, `seed/`. **Не заменяйте** `config.js` (в нём адрес вашего Worker) и `worker/wrangler.jsonc` (в нём ID вашей базы) — архив их не содержит.
5. Необязательно: в `wrangler.jsonc` → `vars` можно добавить `"MAX_UPLOAD_MB": "5120"` (предел размера файла при загрузке по частям; по умолчанию 5120 МБ).
6. Worker из GitHub обновится сам. Проверьте `/health` и откройте админку.

## 2. Развёртывание (только в браузере, без установки программ)

> Я не мог проверить эти шаги на вашем аккаунте Cloudflare — их нужно пройти по порядку и сообщить, если что-то не сошлось.

1. **Аккаунт Cloudflare** (бесплатный). Для R2 может потребоваться привязать банковскую карту; списаний в пределах бесплатных лимитов быть не должно (условия проверьте при регистрации).
2. **База D1:** Storage & Databases → D1 → Create → имя `cad-x-forge`. Скопируйте *Database ID* и вставьте в `worker/wrangler.jsonc` вместо `ЗАМЕНИТЕ_НА_ID_БАЗЫ_D1`.
3. **Миграции:** откройте базу → Console. Вставьте и выполните по очереди содержимое `worker/migrations/0001_init.sql`, затем `0002_reference_data.sql`.
   Если консоль не принимает файл целиком — выполняйте блоками (один `CREATE TABLE`/`INSERT` за раз). Порядок важен.
4. **Хранилище R2:** R2 → Create bucket → `cad-x-forge-files`. **Не включайте публичный доступ** (ни r2.dev, ни свой домен) — файлы выдаёт только Worker.
5. **Worker из GitHub:** Workers & Pages → Create → Import a repository → ваш репозиторий. *Root directory:* `worker`. Deploy command по умолчанию (`npx wrangler deploy`). Привязки D1/R2 и переменные берутся из `worker/wrangler.jsonc`.
   Если ваш адрес GitHub Pages отличается — поправьте `ALLOWED_ORIGIN`, `WEBAPP_URL`, `ADMIN_URL` в `wrangler.jsonc`.
6. **Секреты:** Worker → Settings → Variables and Secrets → добавьте **как Secret**:

   | Имя | Что вписать |
   |---|---|
   | `BOT_TOKEN` | токен бота от @BotFather |
   | `WEBHOOK_SECRET` | длинная случайная строка из латинских букв и цифр (придумайте, 32+ символа) |
   | `ADMIN_TELEGRAM_IDS` | числовые Telegram ID администраторов через запятую (свой ID покажет, например, бот @userinfobot) |
   | `DOWNLOAD_SIGNING_KEY` | ещё одна длинная случайная строка (не такая же, как WEBHOOK_SECRET) |

   Никогда не вставляйте эти значения в код, GitHub или чат. Шаблон для локальной разработки — `worker/.dev.vars.example`.
7. **Подключить фронтенд:** в `config.js` укажите адрес вашего Worker (`https://cad-x-forge-api.<аккаунт>.workers.dev`), закоммитьте. Файл `catalog.js` из старой версии больше не нужен — удалите его из репозитория.
8. **Webhook (один раз):** в приватном окне браузера откройте адрес
   `https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=https://<адрес-worker>/api/telegram/webhook&secret_token=<WEBHOOK_SECRET>&allowed_updates=["message","pre_checkout_query"]`
   (подставьте свои значения; ответ должен содержать `"ok":true`; закройте окно и не сохраняйте адрес — в нём токен).
9. **BotFather:** `/mybots` → ваш бот → *Bot Settings → Menu Button* → URL магазина (`https://…github.io/cad-x-forge/`).
10. **Вход в админку:** отправьте боту `/admin` → нажмите кнопку. Во вкладке **Настройки** нажмите «Подключить бота» (команды и меню бота).
11. **Наполнение:** в админке создайте товар → загрузите главное изображение → загрузите файлы (PDF A4 / PDF Plotter / PLT) → «Опубликовать».
    Демо-товары (необязательно): `seed/demo-products.sql` выполняется в D1 Console; они создаются **черновиками**, для публикации им нужны изображение и файл.

## 3. Локальная разработка и тесты

Нужен Node.js 22+. В папке `worker`: `npm install` (для wrangler), затем `npm test` — запускает 30 автотестов (бэкенд на настоящей SQLite с имитацией D1/R2 и интеграционные тесты, где настоящие `index.html` и `admin/index.html` работают с настоящим Worker). Перетаскивание мышью и касанием тестами не покрыто — проверяйте руками (есть запасные кнопки ▲▼).
Локальный запуск: скопируйте `.dev.vars.example` в `.dev.vars`, затем `npx wrangler dev` (миграции: `npx wrangler d1 migrations apply cad-x-forge --local`).

## 4. Как работает оплата Stars
1. Mini App → `POST /api/cart/checkout`. Сервер проверяет товары (опубликованы, не куплены), считает сумму, создаёт заказ `CFX-YYYY-NNNNNN` и счёт Stars.
2. Mini App открывает счёт через `Telegram.WebApp.openInvoice`. Этот ответ нужен только для интерфейса.
3. Telegram присылает на webhook `pre_checkout_query` — сервер проверяет заказ, пользователя, сумму, доступность и отвечает.
4. Telegram присылает `successful_payment` — в одной транзакции записывается платёж (уникальный `telegram_payment_charge_id`), заказ становится `paid`, создаются покупки. Повторные доставки ничего не дублируют. Бот отправляет сообщение с кнопкой «Мои покупки».
5. Некорректные платежи (чужая сумма/пользователь, двойная оплата одного заказа) доступа не дают, администраторам уходит уведомление; возврат — кнопка «Вернуть Stars» в заказах.

## 5. Безопасность
* Подпись `initData` проверяется на сервере на каждый запрос (срок — 24 часа); админ определяется только по `ADMIN_TELEGRAM_IDS`.
* Файлы: закрытый R2, ссылка живёт 120 секунд, подписана HMAC, при скачивании покупка проверяется заново (после возврата ссылка перестаёт работать).
* Загрузки: белый список форматов из БД, проверка содержимого (PDF/PNG/JPEG/WEBP/PLT), лимиты размера, очистка имён файлов.
* Параметризованные SQL-запросы, CORS только для вашего адреса, секреты только в переменных окружения.
* Если токен бота мог утечь: @BotFather → `/revoke`, обновите секрет `BOT_TOKEN` и повторите шаг 8.

## 6. Чек-лист проверки после развёртывания (проходите вы)
Автотесты уже проверяют логику, но следующее возможно проверить только на живых сервисах:
1. `https://<worker>/health` → `"ok":true`. 2. `/admin` в боте → открывается панель; чужой аккаунт получает отказ.
3. Создать категорию, размер, ростовку, тег. 4. Создать товар, загрузить изображение, PDF A4, PDF Plotter, PLT. 5. Опубликовать → товар виден в магазине на другом устройстве.
6. Поиск и фильтры находят товар. 7. Добавить в корзину → оплатить Stars (рекомендуется минимальная цена, затем «Вернуть Stars»).
8. Появилось сообщение бота об оплате; в «Покупки» — заказ и файлы. 9. Скачать все три файла; открыть. 10. Другой аккаунт не может скачать чужие файлы.
11. Проверка на iPhone, Android и Telegram Desktop (вёрстка, кнопки, загрузка файла на iOS).

## 7. Частые проблемы
* **Магазин пишет «Нет связи с сервером»:** проверьте адрес в `config.js` и `ALLOWED_ORIGIN` (должен совпадать с адресом GitHub Pages без пути).
* **«Подпись Telegram неверна»:** `BOT_TOKEN` не от того бота, из которого открыт Mini App.
* **Оплата не проходит / нет сообщения:** проверьте webhook: `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` (поле `last_error_message`) и секрет `WEBHOOK_SECRET`.
* **Не публикуется товар:** нужны название, цена ≥ 1 ★, категория, изображение и файл (подсказка покажет, чего не хватает).
* **Файл не скачивается на iPhone:** используйте кнопку «Скачать» внутри Telegram; ссылка действует 2 минуты.

## 8. Варианты размер × рост, большие файлы, страницы

* **Варианты.** В карточке товара (после первого сохранения) выберите размеры и ростовки → «Создать сочетания». Для каждого сочетания переключатель «в наличии» и свои файлы («Файлы»). Общие файлы товара (нижний раздел) получает любой покупатель. Покупатель выбирает размер и рост, платит и получает файлы **только своего сочетания** плюс общие. Недоступное сочетание видно, но не покупается. Публикация требует файл для каждого доступного варианта (своего или общего).
* **Большие файлы.** До 20 МБ — одним запросом, больше — по частям (8 МБ) с индикатором и **продолжением**: после обрыва выберите тот же файл ещё раз. Предел задаёт `MAX_UPLOAD_MB`. Реальные ограничения платформы (размер запроса к Worker, лимиты и стоимость R2) проверьте в документации Cloudflare для вашего тарифа. Видео (формат `mp4` добавляется в «Справочники → Форматы файлов») смотрится в магазине через кнопку «Смотреть» (поток по Range, ссылка действует 1 час). Многогигабайтные файлы загружайте с компьютера, не с телефона.
* **Страницы и меню.** «Страницы»: «Инфо» и FAQ редактируются блоками (заголовок, текст, вопрос-ответ, кнопка, изображение) на трёх языках; можно создать юридические документы и обычные страницы и добавить их в «Меню». Тексты документов вы готовите сами; **юридическую проверку (персональные данные, договор-оферта, фискальные чеки в Казахстане) проведите до запуска продаж.**
* **Справочники.** Колонки slug, «Родитель», «Порядок», «Скрыть», «Фото» убраны; slug создаётся автоматически; у категории выбирается аудитория. Порядок меняется перетаскиванием за значок ⠿, «Убрать» переносит запись в неиспользуемые (данные не удаляются).
